## What you will understand

By the end of this lesson, you should be able to explain cloud computing as an operating model, recognize its essential characteristics, and describe how the three providers fit into the same mental model.

## Begin with the problem

Imagine that a small company wants to launch an application. Without cloud computing, the company may need to estimate demand, buy physical servers, wait for delivery, prepare a room, install hardware, configure networks, and maintain spare capacity for busy periods.

If demand is lower than expected, expensive hardware sits unused. If demand is higher than expected, customers experience slow responses while the company waits for more equipment.

Cloud computing changes how the company obtains those computing resources.

## A plain-language definition

Cloud computing is a way to obtain configurable computing resources over a network when they are needed, provision them quickly, and measure their use.

Those resources can include processing power, storage, networks, databases, application platforms, and complete applications.

The important idea is not that the computers are floating somewhere. The important idea is that computing becomes an accessible service rather than equipment that every customer must purchase and operate alone.

:::note[Standards definition]
NIST Special Publication 800-145 describes cloud computing using five essential characteristics, three service models, and four deployment models. The wording above is a beginner-friendly interpretation, not a replacement for the formal definition.
:::

## Everyday analogy: electricity from a utility

Most homes do not operate a private power station. A utility operates large shared infrastructure. You connect to the service, consume electricity when needed, and a meter records usage.

### Where the analogy stops

Electricity is comparatively uniform. Cloud services are not. A virtual machine, object store, managed database, and event queue have different behavior, configuration, security responsibilities, and pricing dimensions.

The analogy helps explain the operating model. It does not explain the architecture of every service.

## The five essential characteristics

### 1. On-demand self-service

A consumer can provision capabilities without waiting for a provider employee to perform each request manually. A developer may create a test resource through a console, command-line tool, or API.

### 2. Broad network access

Capabilities are available over networks through standard mechanisms used by different kinds of clients. This does not mean every resource must be exposed to the public internet. Private connectivity is still network access.

### 3. Resource pooling

The provider pools resources to serve multiple consumers. Physical and virtual resources are assigned and reassigned according to demand. Security and isolation controls keep one customer's workload logically separated from another.

### 4. Rapid elasticity

Resources can expand and contract as demand changes. To the consumer, available capacity can appear very large. Elasticity is about changing capacity with demand, while scalability is the broader ability of a system to handle growth.

### 5. Measured service

Cloud systems measure resource usage. Measurement supports monitoring, reporting, capacity management, and consumption-based billing. It does not mean every service uses the same unit or price model.

## Service models answer: how much do you manage?

### Infrastructure as a Service

IaaS provides foundational resources such as virtual computing, storage, and networking. You generally retain more control and more operational responsibility.

### Platform as a Service

PaaS provides a managed platform on which you deploy applications. The provider manages more of the underlying operating environment, allowing you to focus more on application code and data.

### Software as a Service

SaaS provides a complete application that you use. You still manage matters such as users, access, configuration, and the data you choose to place in the application.

```text
More customer control and responsibility
                |
                v
              IaaS
                |
              PaaS
                |
              SaaS
                |
                v
More provider-managed technology
```

:::caution[Service categories are starting points]
Real services do not always fit perfectly into one label. Always check the responsibility documentation for the particular service you use.
:::

## Deployment models answer: who uses and operates the environment?

- **Public cloud:** Cloud infrastructure is available for use by multiple organizations and is operated by a cloud provider.
- **Private cloud:** Cloud infrastructure is provisioned for exclusive use by one organization.
- **Community cloud:** Infrastructure is provisioned for a specific community of organizations with shared concerns.
- **Hybrid cloud:** Distinct cloud environments remain separate but are connected to support portability or coordinated operation.

## Where the three providers fit

AWS, Microsoft Azure, and Google Cloud are public cloud platforms. Each provides many services covering infrastructure, managed platforms, data, security, analytics, application development, and operations.

## How provider mappings should be read

A provider mapping answers a narrow question: which services address a similar need? It does not claim that their settings, limits, security controls, pricing, regional availability, or surrounding tools are identical.

| Vendor-neutral capability | AWS        | Microsoft Azure        | Google Cloud   | Mapping confidence | Important boundary                                                                                          |
| ------------------------- | ---------- | ---------------------- | -------------- | ------------------ | ----------------------------------------------------------------------------------------------------------- |
| Virtual machines          | Amazon EC2 | Azure Virtual Machines | Compute Engine | Direct             | All provide customer-configured virtual compute, but machine families, disks, networking, and tooling vary. |
| Object storage            | Amazon S3  | Azure Blob Storage     | Cloud Storage  | Direct             | All store objects in cloud containers, but namespaces, storage classes, permissions, and features vary.     |

**Why “direct” does not mean “identical”:** each row maps a stable capability with substantially comparable customer responsibility. A migration still requires a feature-by-feature design review. Later compute and storage lessons examine those differences in depth.

## A realistic starter architecture

Imagine a small team operating a web application. The team uses several cloud capabilities together rather than buying one product called “the cloud.”

### Read the request path step by step

1. A user reaches a network endpoint through a standard network protocol.
2. A load balancer sends the request to an available application instance.
3. Several instances allow capacity to change and reduce reliance on one process.
4. The application reads structured records from a managed database and files from object storage.
5. Identity and access rules decide which people and software may perform actions.
6. Monitoring and usage records help operators see behavior, investigate problems, and understand consumption.

### Where the five characteristics appear

| Characteristic         | Example in the architecture                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| On-demand self-service | The team provisions application, storage, and monitoring resources through provider tools. |
| Broad network access   | Users and components communicate over defined network interfaces.                          |
| Resource pooling       | The provider allocates underlying capacity from shared pools while isolating customers.    |
| Rapid elasticity       | Application capacity can grow or shrink as demand changes.                                 |
| Measured service       | Usage records make consumption visible for operations and billing.                         |

This diagram is a teaching architecture, not a production guarantee. Real systems also need decisions about regions, failure recovery, backups, encryption, secrets, deployment, cost controls, and service-specific limits.

## What cloud computing does not guarantee

Cloud computing does not automatically make an application secure, highly available, inexpensive, compliant, or well designed. Providers supply capabilities and operate defined parts of the system. Customers must still select, configure, monitor, and use those capabilities appropriately.

## Common beginner confusions

### Cloud means public internet

False. Cloud resources can use private addressing, private endpoints, dedicated connections, and access controls. The provider operates shared infrastructure, but your workload does not need to be publicly reachable.

### Cloud means serverless

False. Cloud platforms offer virtual machines, containers, physical hosts, managed platforms, serverless services, and many other operating models.

### Pay for use always means cheaper

False. Consumption pricing changes how cost is incurred. Poor sizing, idle resources, unnecessary data transfer, and weak governance can still produce high bills.

### Managed means no responsibility

False. A managed service changes the responsibility boundary. It does not eliminate customer responsibility for data, identity, access, configuration, and workload design.

## Workplace and interview context

### What a beginner may do at work

A junior cloud practitioner is unlikely to “manage the whole cloud.” A first task may be smaller and more concrete:

- identify whether a request needs a virtual machine, a managed platform, or an existing SaaS tool
- create a development resource from an approved template
- record its owner, purpose, environment, and cost tag
- confirm that network access is private or intentionally public
- check monitoring and usage information
- remove temporary resources after the work finishes
- explain which tasks remain with the team after selecting a managed service

```text
Work request
     |
     v
Clarify the need
     |
     +--> What capability is required?
     +--> Who manages each layer?
     +--> Who may access it?
     +--> How will use and health be measured?
     +--> When should it be changed or removed?
     |
     v
Provision, verify, document, and review
```

### A useful interview answer

If asked “What is cloud computing?”, begin with the operating model rather than listing provider products:

> Cloud computing provides configurable computing resources as network-accessible services that can be provisioned quickly and measured. Its essential characteristics include on-demand self-service, broad network access, resource pooling, rapid elasticity, and measured service. Service and deployment models then explain responsibility and who uses the environment.

Then add one boundary: cloud use does not automatically make a workload secure, reliable, or inexpensive. That sentence shows that you understand both the value and the limits of the model.

## Glossary

| Term                              | Beginner-friendly meaning                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Cloud computing                   | An operating model for obtaining configurable computing resources as rapidly provisioned, measured services. |
| Provision                         | Create or allocate a resource so it is ready to use.                                                         |
| Resource                          | A usable computing capability, such as processing, storage, networking, a database, or an application.       |
| Workload                          | The application, service, data processing job, or other work that runs on computing resources.               |
| Elasticity                        | Increasing or decreasing capacity as demand changes.                                                         |
| Scalability                       | A system's broader ability to handle growth or reduction in work.                                            |
| Resource pooling                  | A provider serving many consumers from shared capacity while maintaining appropriate isolation.              |
| IaaS                              | Infrastructure as a Service, where the customer controls more of the operating stack.                        |
| PaaS                              | Platform as a Service, where the provider manages more of the application platform.                          |
| SaaS                              | Software as a Service, a complete provider-operated application that a customer configures and uses.         |
| Public cloud                      | Cloud infrastructure offered for use by multiple organizations and operated by a provider.                   |
| Virtual machine                   | A software-defined computer with allocated processor, memory, storage, networking, and an operating system.  |
| Object storage                    | Storage that keeps data as objects inside containers, commonly called buckets or containers.                 |
| Application programming interface | A defined way for software to request actions or data from another system, commonly shortened to API.        |

## Recap

- Cloud computing delivers configurable computing capabilities as services.
- On-demand access, network access, resource pooling, elasticity, and measurement are essential characteristics.
- Service models describe how responsibility is divided across the technology stack.
- Deployment models describe how cloud infrastructure is made available and combined.
- AWS, Azure, and Google Cloud express the same broad concepts through different services and management systems.
- Cloud capabilities still require sound customer decisions.
